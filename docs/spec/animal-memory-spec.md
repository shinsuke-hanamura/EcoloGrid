## 0. 確定事項(作者指示)
1. **記憶は 2 種類**。**短期記憶**: 行動・出来事のたびに追加される経験のログ(件数の上限なし。**寝たら整理されて空になる**)。**長期記憶**: 整理された記憶(集計表)。**将来は RL に代替される**。**短期記憶は、RL の経験バッファ(経験ログ)を兼ねる**(§3.2)。
2. **記憶するのは「action と場所」(出来事も含む)**。**記憶の強さは残す**: **強さ = (1 + \|reward\|) × 乱数(0〜1)**(記録のたびに決める)。嗜好 0 のどうでもよいものを食べた記憶も、0 ではなく弱く記憶されうる。**標準の嗜好を +10 にする必要はない**。
3. **整理は、入眠時・意識消失時のみ**。順序: **(1) 忘却(全長期記憶に忘却係数をかけ、忘却閾値を下回ったものを削除)→ (2) 短期記憶を長期記憶に統合 → (3) 短期記憶を空にする**(§4.3)。入眠しない個体は整理されない(安全弁なし)。**薄まる機構は、忘却に一本化**(`forgetting_factor`・`forgetting_threshold`。個体ごと・種ごと)。
4. **類似の判定は、丸めた座標が同じこと**。丸めの距離 D は action ごと(`drink`・`rest` が 2、それ以外が 4)。**D は記憶ごとに座標とともに保存**(将来、記憶ごとに変えられる)。長期記憶の座標は最初の記憶の座標。強さは加算。報酬の合計を持つ。
5. **記憶の打ち消しはしない**。同じ行為・状況で、ある時は reward が得られ、別の時は得られなかった、という**ログが蓄積される**(結果ごとの長期記憶が並存する)。
6. **想起**: A(目標指向。**記憶の強さに比例する選択**。§4.4)と B(場所による。強い記憶ほど思い出しやすい。§4.5)。B: 確率 `1 − exp(−強さ/τ)`(τ = 5)、上限 3 件、不応期 600 tick(個体ごと・種ごと)。隣の区画は見ない。
7. **eat**: `eat_reward` は持たず内部で計算。**`ate` の reward = 嗜好**。**吸収性**は行動の選択と無関係(Energy・毒性の吸収の割合。現行を維持: Rabbit 0.5・Fox 0.6・Player 0.6)。嗜好・吸収性は個体ごと・種ごと(食べ物ごと)に持ち、種の標準値を発生時にコピー(当面は個体差なし)。
8. **知覚**: 個体ごとに範囲を持つ(PC を含む。種の標準値を発生時にコピー。将来は遺伝子)。**有効な範囲 r = 範囲 × 覚醒度の割合**(切り捨て)。**Player の標準値は 20**。**知覚するのは「自分のセル + 距離 r まで」(チェビシェフ距離 = 正方形。r = 0 なら自分のセルだけ)。距離の方式は、すべての知覚(獲物・水の探索を含む)でチェビシェフ距離に統一**。**UI には、知覚の範囲しか見せない**(サーバ側で PC ごとに絞る)。
9. **NPC(動物・人間)の判断は、世界への直接の問い合わせから、知覚した地図への問い合わせに切り替える**(確定)。**経験の `state` の地図の範囲は、知覚の範囲**(§3.2)。**整理の直前に、RL のリプレイを行う設計**(確定)。**地図の更新の周期は、個体ごと・種ごとの設定値**(当面は全種・全個体同じ。個体は発生時に、種の標準周期を採用)(§8)。
9b. **PC も NPC と同じ知覚・判断を計算し、行動はプレイヤーが決める**。助言(advice)の API は了承済み。記憶の API は本人のみ + 管理 API。
10. 名前: `Action`・`Outcome`・`reward`・`Experience`。`saw_kin` はこのまま(将来の同種の個体。§7)。**RL はゲート方式(測って判断)で進める**。
11. `faint`・`near_death` は記憶しない。「生命に関わる」の区分は不要。
12b. **確定(作者回答 2026-11-10)**: 経験の `state` の地図は**参照を既定**とし、**全ステップのログ(`memorise_all_steps`)のときだけ窓のコピー**。目標指向の想起は**強さに比例する選択**で、結果の分類(目標・失敗・忌避)で向かう・外すを決め、**距離の割引 κ は当面 0**。**判断の順序は「地図 → 想起 → 探索」**。**標準の嗜好は当面 0**。**全ステップのログのフラグは `memorise_all_steps`**(ワールドの設定、既定オフ)。**地図の更新の周期は 20 tick から始める**。
12. 「今日の出来事」の記録(記憶ではなく)は別途(記録媒体が要る。ペンと紙。将来、物(物資)を導入)(G-44)。

## 1. 現状の整理
- **人間(`Player`)は、すべて PC**。AI が動かす人間は存在しない(AI の `think` は Rabbit・Fox だけ)。
- **「見る」は、現状、action として扱われていない**: コードに `look` はなく、AI の `think` が、**世界(Region)へ直接問い合わせる**(`nearest_water`〔マンハッタン距離の 2 倍〕・`nearest_prey`〔チェビシェフ距離〕)だけ。イベントも、コストも、記憶もない。個体は、見たものを覚えていない。
- **前回の私の仕様案は、`look` を Action(結果 `saw_*`)としていた**。これは、RL の枠組みの定式化(知覚は観測、観測は状態の一部)とは合わない(§2)。**今回、`look` を action から外し、知覚した地図(state)の更新にする**。

## 2. 用語と RL の枠組み
| 概念 | 内部名 | RL の用語 | 内容 |
|---|---|---|---|
| 行動 | `Action` | action (a) | `drink`・`eat`・`rest`・`sleep`・`tell`(将来) |
| 結果 | `Outcome` | observation の一部 | `drank`・`no_water`・`ate`・`no_prey`・`rested`・`slept`・`hurt`・`born` |
| 数値の結果 | `reward` | reward (r) | 表から(`ate` は嗜好) |
| **知覚した地図** | **`PerceptMap`** | **state (s) の一部**(信念状態) | **それまでに知覚した地図**。**見ることで更新される** |
| 記憶 1 件 | `Experience` | experience (s, a, r, s') | 行動 + 結果 + 場所 + reward + **state(地図)** |
- **「見る」= 知覚**は、action ではなく、**観測の処理**。知覚の結果は、**地図の更新**として、状態に入る。action の際の状態 s は、**それまでに知覚した地図(+ 内部状態 + 位置)**。
- 利点: (1) RL(POMDP)の定式化に合う。(2) **「見る」の記録の氾濫(1 日に数千件)の問題が、なくなる**(地図の更新は、記憶の件数を増やさない)。(3) 地図は、経路探索・目標指向の想起の土台になる。
- `Action` は、`ScheduledAction`(周期アクション)と名前が衝突しないように実装する(`memory.Action`)。自分の行動を伴わない出来事は、`Action` = `none`(`idle` に改める案は `docs/research/animal-memory-rl-notes.md` §8.3)。

## 3. 記憶の持ち方

### 3.1 知覚した地図(`PerceptMap`)= 状態(提案)
個体ごとに持つ、**それまでに知覚したものの地図**。**見ることで更新される**。層を分ける。
| 層 | 解像度 | 内容 | 更新・薄まり |
|---|---|---|---|
| 地形 | **セル**(世界の大きさの 1 バイト配列。0 = 未知、1 = 陸、2 = 水、3 = 岩) | 知覚した範囲の地形。経路探索(既知の陸だけを BFS)と、水の位置に使う | 見た範囲で更新。**地形は静的なので、薄めない** |
| 資源 | **区画(D = 4)** | 区画ごとの、食料(植物)の種類別の件数と、見た tick。将来、捕食者・同種の個体(`saw_threat`・`saw_kin`)の層 | 見た範囲で更新(見えた分だけ更新)。**入眠のたびに、件数に忘却係数をかけ、小さくなったものを削除**(忘却のパラメータを共有) |
- **動く個体(獲物など)**: 位置が古くなりやすいので、地図には、**短い期間(例: 数十 tick)だけ**残す、または、現在の視界のみとする案。植物・水は、静的・準静的なので、地図に残す。
- **更新の頻度と負荷**: **地図の更新の周期(`perception_interval_ticks`。個体ごと・種ごとの設定値。§8)ごとに**、範囲 r のセルを走査する。(2r+1)² セル(Rabbit r = 6 で 169、Player r = 20 で 1,681)。**地形は、すでに知っているセルを飛ばす**ので、探索がすめば、ほぼ 0。資源の層も、同じ周期で更新する(以前の案の、資源だけ 600 tick は取り下げ)。Region に**区画ごとの個体の索引**があれば、走査が軽くなる(高速化の提案 C2 と共通)。
- **メモリ量**: 地形 16 KB(128×128)/ 個体、資源 数 KB。個体 1,000 匹で約 20 MB。
- **NPC の判断の入力は、世界への直接の問い合わせでなく、この地図**にする(確定。動物・人間とも。`nearest_water`・`nearest_prey` を、地図への問い合わせにする)。**「見える範囲」は、地図の更新の範囲**になり、方策(RL)は、地図(= 状態)だけを見て決める。

### 3.2 短期記憶 = 経験ログ(RL の経験バッファ)の 1 件(`Experience`)
**短期記憶は、1 日の行動・出来事が、ログのように追加(append)されたもの**。**RL の経験バッファ**を兼ねる(別に「経験ログ」を持たない。作者提案)。
| 項目 | 内容 |
|---|---|
| `tick` | 記録した絶対 tick(ログは tick の順) |
| `action`, `outcome`, `subject` | 小さな整数 ID |
| `x`, `y`, `d` | 場所(世界の通し座標)と、この記憶の丸めの距離 D |
| `reward` | 結果の数値(符号あり) |
| **`strength`** | **(1 + \|reward\|) × 乱数(0〜1)**。決定論的な乱数(seed・個体 ID・tick・action から) |
| **`state`** | **action の際の状態**: 内部状態(渇き・空腹・体力・スタミナの深さ、各 1 バイト程度)+ **知覚の範囲の地図**(§3.2.1)= 中心 (`cx`, `cy`)・有効な範囲 `r`・`map_version` |
### 3.2.1 経験の `state` の地図 = 知覚の範囲(作者指示)
- **経験の `state` に含める地図の範囲は、その時の知覚の範囲**(自分のセル + 距離 r までの (2r+1)×(2r+1) セル。r = その時の有効な範囲)。以前の「3×3 区画の要約」は取り下げる。
- **持ち方(提案)**:
  | 方式 | 内容 | 大きさ(1 件) | 備考 |
  |---|---|---|---|
  | **A. 参照(既定・推奨)** | 中心・`r`・`map_version` だけ持つ。地図の中身は、日中の地図の更新のログ(`MapUpdate`)から**再構成する**(整理の直前のリプレイのときに作る) | 約 16 バイト | 軽い。ログを整理で空にするまでの間だけ再構成できる(リプレイは整理の直前に行うので足りる) |
  | B. コピー | (2R+1)×(2R+1) の窓(R = 種の標準の範囲)に、有効でないセルを「未知」として詰めたものを、1 バイト/セルで持つ | Rabbit 169 B / Fox 289 B / **Player 1.7 KB** | 固定長で、学習データにそのまま使える。重い |
  - 既定は A。**全ステップのログ(§3.6)を有効にするとき**、または外部へ書き出すときに、B で具体化する。
  - 窓は**中心に対する相対座標(自己中心)**にすると、場所によらない学習に向く。
- **状態は、短期記憶(経験ログ)にだけ持つ**。長期記憶への統合のとき、状態は捨てる(長期記憶は、場所と結果の集計)。RL の学習(段階 2 以降)は、経験ログ(短期記憶)から行う(整理の直前に、リプレイ)。
- **ログに入れる範囲**: 当面は、記憶する行為・結果・出来事(§7)だけ。RL の学習用の全ステップ(移動・待機)は、設定(フラグ)で有効にする(段階 4。負荷が大きい)。

### 3.3 長期記憶の 1 件(`LongEntry`)
| 項目 | 内容 |
|---|---|
| key = (`action`, `outcome`, `subject`, `d`, `bx`, `by`) | `bx = x // d`、`by = y // d`。**結果(`outcome`)ごとに別の項目**(`drank` と `no_water` は別。打ち消さない) |
| `x`, `y` | 最初の記憶の座標(歩いて行ける代表点) |
| `count` | 統合した件数(忘却で小数になる) |
| `reward_sum` | 報酬の合計。**平均報酬 = reward_sum ÷ count** |
| **`strength`** | **強さの合計**(各記録の `(1 + \|reward\|) × 乱数` の合計)。想起の確率・忘却の閾値に使う |
| `first_tick`, `last_tick` | 最初・最後の tick |

### 3.4 個体の記憶(`Memory`)
```
Memory:
  map:  PerceptMap                                  知覚した地図(状態)。個体の状態として持つ(睡眠で消えない)
  log:  list[Experience | MapUpdate]                短期記憶(経験ログ)。上限なし。入眠まで追加のみ。寝たら整理して空。
                                                    MapUpdate = 地図の更新の差分(日中の状態の再構成用。経験の `map_version` と対応)
  long: dict[LongKey] → LongEntry                   長期記憶(集計表)
  d_values: set[int]                                この個体の記憶にある D の種類(通常 {2, 4})
  place_index: dict[(d, bx, by)] → list[記憶]        場所による想起用。ログは追加のたびに、長期は整理のたびに更新
  long_index: dict[(action, subject, d, bx, by)] → 区画の集計    目標指向の想起用(§4.4)
```
- `Animal.memory`(Player も同じ)。公開用 `to_dict()` に含めず、内部状態用の `memory.to_state()`(コンパクトな配列)で、越境・永続化に使う。

### 3.5 類似の判定: 丸めた座標の一致
`同じ key = (action, outcome, subject, d, x // d, y // d)`。同値関係(推移的)・ハッシュで O(1)。隣の区画は見ない(確定)。D を記憶ごとに持つので、将来、記憶ごとに丸めを変えられる。

### 3.6 全ステップのログのフラグ(`memorise_all_steps`)の説明
- **何か**: 経験ログ(短期記憶)に、**どの行動を記録するか**の設定。
  - **オフ(既定)**: **記憶する行為・結果・出来事だけ**(§7.1: 飲水・捕食・休憩・睡眠・失敗・出来事)。1 日に数十〜数百件。
  - **オン**: **AI が判断するたびの、すべてのステップ**(移動の方向・待機・食べ物へ向かうなど、**reward がほぼ 0 の行動を含む**)を、経験ログに追加する。
- **なぜ要るか(RL)**: 強化学習は、**毎ステップの (状態, 行動, 報酬, 次の状態)** から学ぶ。「どの方向へ歩くか」という移動の方策を学習するには、移動のステップも要る。オフのログは、疎(reward のあるステップだけ)で、価値の更新(段階 2)には足りるが、**移動の方策の学習(段階 5)には足りない**。
- **なぜフラグ(設定)にするか(負荷)**: 1 日の判断の回数(判断の周期から)と、状態を含めた大きさ:
  | 種 | 判断の周期 | 1 日の step 数 | 状態を参照(約 16 バイト)で持つ | 状態を窓のコピー(知覚の範囲)で持つ |
  |---|---|---|---|---|
  | Rabbit | 20 tick | 4,320 | 約 70 KB/日 | 約 0.7 MB/日(13×13 セル) |
  | Fox | 12 tick | 7,200 | 約 115 KB/日 | 約 2.1 MB/日(17×17) |
  | Player | 5 tick | 17,280 | 約 280 KB/日 | **約 29 MB/日**(41×41) |
  - 個体数が増えると、メモリと、整理(リプレイ)の時間が増える。**通常の運用では不要なので、既定はオフ**。学習用のシミュレーション(ヘッドレス)でだけ、オンにする。
- **設定の範囲(提案)**: ワールドの設定(`WorldConfig.memorise_all_steps`、既定 false)。将来、種・個体ごとに上書きできる(学習する対象の種だけオン、など)。
- **オンのときの扱い**: 全ステップのエントリは、**RL のリプレイにだけ使い、長期記憶には統合しない**(長期記憶は、記憶する行為・結果・出来事だけ)。整理のとき、リプレイのあと、ログとともに空にする。状態は、方式 B(窓のコピー。§3.2.1)で具体化できる。

## 4. 記憶の流れ

### 4.1 知覚(地図の更新)
```
perceive():                                          # 地図の更新の周期(perception_interval_ticks)ごと。睡眠中はしない(r = 0)
    r = floor(perception_range × 覚醒度の割合)        # 有効な範囲。自分のセル + 距離 r(チェビシェフ距離)まで
    範囲内の地形・資源を読み取り、map を更新(未知のセルを既知にする。資源の件数と tick を更新)
    更新の差分を log に MapUpdate として追加(日中の状態の再構成用)
```
- **記憶(長期)には、直接入らない**。地図が、それまでの知覚を持つ。

### 4.2 記録(action・出来事のたび): ログへの追加
```
record(action, outcome, subject, x, y, tick):
    r = reward(species, action, outcome, subject)            # 表(`ate` は preference[subject])
    s = (1 + abs(r)) * rng.random()                           # 強さ。決定論的な乱数
    log.append(Experience(tick, action, outcome, subject, x, y, d(action), r, s, state = 内部状態 + 地図の要約 + map_version))
```
- 行為は起きるたびに追加(飲水 6 回 = 6 件)。O(1)。「見る」の記録規則(同じ key を 1 回)は、**不要になった**(「見る」は記録でなく地図の更新)。

### 4.3 整理(入眠時・意識消失時のみ)
```
organize():
    # (0) (任意)RL: 経験ログのリプレイ(学習の更新)。段階 2 以降。
    # (1) 忘却: 全長期記憶に忘却係数をかけ、忘却閾値を下回ったものを削除。地図の資源の層にも同様
    for e in long.values():  e.count *= forgetting_factor;  e.reward_sum *= forgetting_factor;  e.strength *= forgetting_factor
    long から、strength < forgetting_threshold のものを削除
    # (2) 統合: 経験ログを、長期記憶に統合(今日の分は、今回は忘却されない。state は捨てる)
    for m in log (Experience のみ。古い順):
        e = long.get(key(m))
        if e: e.count += 1; e.reward_sum += m.reward; e.strength += m.strength; e.last_tick = m.tick
        else: long[key(m)] = 新しい長期記憶(m の座標・d、count = 1、reward_sum = m.reward、strength = m.strength、first/last_tick = m.tick)
    # (3) 経験ログを空にする。索引を作り直す
    log.clear();  place_index・long_index を作り直す
```
- 強さ・件数・報酬の合計に、同じ係数をかけるので、平均報酬は忘却で変わらない。入眠しなければ、忘却も整理も起きない。

### 4.4 目標指向の想起(A)— 記憶の強さに比例する選択(作者指示 2026-11-10)
**reward でなく、記憶の強さに比例して、ランダムに選ぶ。** 嗜好 0 の食べ物も、強さは 0 でない(弱いが残る)ので、**想起は弱いが、食べようとするようになる**。
```
recall_goal(action, subject, 現在地):
    for 区画 b in 長期記憶と当日のログの、同じ (action, subject) の区画:
        # (1) 区画の代表の結果: 区画の全結果から、強さに比例する確率で 1 つ選ぶ(決定論的な乱数)
        o_b = sample(区画 b の結果, 重み = 結果ごとの強さ)
        if o_b の分類 が「目標」でない: 区画 b を候補から外す        # 失敗(no_water)や忌避(hurt)が選ばれた区画には、向かわない
        w_b = o_b の強さ  (× 1 / (1 + 距離)^κ)                     # 当面 κ = 0(強さだけに比例)
    if 候補がない: 地図の既知の資源へ(§4.4.1)
    return sample(候補の区画, 重み = w_b) の座標(最初の記憶の座標)
```
- **選ぶのは「強さ」**: 区画の代表の結果の選択も、区画どうしの選択も、**強さに比例**する(reward の値は、選択に使わない)。reward は、**結果の分類**(目標・失敗・忌避)を通じてだけ効く(強さは (1 + \|reward\|) × 乱数なので、reward の大きさは、強さを通じて間接的に効く)。
- **結果の分類**(§7.1 の列): **目標**(`drank`・`ate`・`rested`・`slept`・`born` など。そこへ向かう理由になる)、**失敗**(`no_water`・`no_prey`)、**忌避**(`hurt`)。**嗜好が負(嫌い)でも `ate` は「目標」**(分類で決まり、reward の符号では決めない)。
- 例: 区画 X で、`drank`(強さ 40)と `no_water`(強さ 4): `drank` が代表になる確率 91%(向かう候補)、`no_water` が 9%(その区画は、今回は候補から外れる)。**失敗が増えるほど、候補から外れる確率が上がる**。
- 打ち消しの規則は不要(確定): 結果ごとの記憶が並存し、想起のたびに強さに比例して選ばれる。確率的な選択は、探索にもなる(Thompson sampling に近い)。
- **距離の割引 `κ`**(`recall_distance_exponent`): 当面 0(強さだけに比例)。1 にすると、`強さ / (1 + 距離)` に比例し、近い場所が選ばれやすくなる(要確認。試験で決める)。
- 計算量: 想起は、渇き・空腹で、地図に目標がないときだけ。区画は、その action の長期記憶の区画(通常 数十)。各区画の結果は少ない(1〜3)。O(区画数)。

#### 4.4.1 地図への切り替え(確定)と、記憶がないときの代替
**判断の順序**(渇き・空腹のとき): (1) 地図(現在の知覚の範囲を含む)に、目標(水・食料)が既知なら、**地図から最寄りの目標**へ向かう。 (2) 地図に目標がなければ、**想起(A)**で、記憶した場所へ向かう。 (3) 想起もなければ、地図の既知の資源のうち最寄りへ、なければ探索(ランダムな移動)。
- 地図は「いま見えている・見たことがある」場所、想起は「(地図に載っていないが)行為を覚えている」場所、という役割。(1) と (2) の優先は、要確認(想起を先にして、強い習慣を使う案もある)。

### 4.5 場所による想起(B)
- **「同じ場所」の判定**: 記憶が持つ D で、現在地を丸めて比べる。その個体の記憶にある D の種類(`d_values`)ごとに `place_index[(d, x // d, y // d)]` を引く(辞書引き数回)。
- **想起の確率(確定)**: `p = 1 − exp(−強さ / τ)`、**τ = `recall_tau` = 5**。強さ = 長期記憶では `strength` の合計、経験ログの 1 件では、その `strength`。強さ 1 → 0.18、2 → 0.33、5 → 0.63、10 → 0.86。繰り返した場所は強さが加算されるので、ほぼ確実に思い出される。
- **件数の上限 `recall_max` = 3**、**不応期 `recall_refractory_ticks` = 600**(個体ごと・種ごと)。区画に入ったとき(前回の判定と区画が変わったとき)に判定。判定の乱数は決定論的。
- 結果(`recalled`)は、状態(RL の観測)の特徴・NPC の判断の材料・PC の助言の材料。想起による強化は、当面しない。

## 5. 薄まる機構・強さと reward・打ち消し(解決済み)
- **薄まる機構は、忘却に一本化**(確定)。長期記憶と、地図の資源の層に、`forgetting_factor`・`forgetting_threshold`。
- **「見る」の氾濫の問題は、「見る」を地図の更新にしたことで解決**(記憶の件数が増えない)。
- **強さ = (1 + \|reward\|) × 乱数**(確定): reward の大きさが大きいほど強く、reward が 0 でも 0 にならない(弱く記憶される)。強さと reward は、別の項目として残る(強さ = 顕著さ、reward = 価値)。
- **打ち消しは不要**(確定): 同じ行為・状況の、異なる結果は、別の項目として並存し、**想起のとき(§4.4)に、強さに比例して選ばれる**。
- 忘却のパラメータの目安(暫定 0.9・0.5。強さの平均 = (1 + \|r\|) × 0.5): 1 回の飲水(強さ 平均 5.5)は約 **22 日**(= 22 回の入眠)残る。嗜好 0 の食べ物(強さ 平均 0.5)は、1 回目の忘却(0.45 < 0.5)で消える → **嗜好 0 のものは、1 回では残らず、繰り返さないと長期記憶に残らない**(「どうでもよいものは、よく忘れる」)。毎日 6 回飲む場所は、強さ 約 33/日 → 約 330 に落ち着く。

## 6. 処理負荷
- **記録は O(1)**。ログの大きさは、1 日に数十〜数百件(行為 + 出来事 + MapUpdate)。**整理は O(ログ + 長期記憶)**(1 日 1 回)。長期記憶は忘却で増え続けない(1 個体で数十〜数百件)。
- **地図**: 知覚(AI の考える周期)で、範囲のセルを走査。地形は既知を飛ばす。区画の索引で軽くできる。地図 約 20 KB / 個体。
- 想起 A: 索引の降順 + 打ち切りで、数区画。想起 B: 区画に入ったときだけ、辞書引き数回。
- 入眠しない個体は、ログが増え続ける(安全弁なし。管理 API で件数を監視)。

## 9. eat の報酬・嗜好・吸収性
- `eat_reward` は持たず、**`ate` の reward = `preference[subject]`**(動物・人間は吸収した Energy を知るすべがなく、嗜好を頼りにする)。**`absorption[subject]`** は行動の選択と無関係で、eat のとき、**得る Energy = 獲物の Energy × `absorption`**、**(将来)毒性の吸収 = 獲物の毒性 × `absorption`**(現行の `energy_absorption_rate` を置き換える)。
- 例(将来): **タバコ** = 嗜好が高く、毒性があり、吸収性が低い(0.2)→ 食べたがるが、吸収は 2 割。
- 嗜好・吸収性は、個体ごと・種ごと(食べ物ごと)に持ち、種の標準値を発生時にコピー(個体差なし)。内部状態に含め、公開用 `to_dict()` には含めない。
- **標準の嗜好と、食料の想起(§4.4。作者指示で改訂)**: 強さが `(1 + |r|) × 乱数` なので、嗜好 0 でも `ate` の記憶は弱く残りうる。**目標指向の想起は、reward でなく強さに比例して選ぶ**ので、**嗜好 0 の食べ物も、想起は弱いが、食べようとするようになる**(`ate` は、嗜好が 0 でも負でも、結果の分類は「目標」)。したがって、**標準の嗜好を +10(や正の値)にする必要はなく、当面 0 でよい**。嗜好を上げると、強さが大きくなり、想起されやすく、よく向かうようになる。
- 嗜好 0 の記憶は、強さの平均が 0.5(= (1 + 0) × 0.5)で、忘却(0.9・0.5)の 1 回目で消えやすい。**繰り返し食べれば、強さが加算されて残る**。

## 10. 知覚の範囲と UI
- 個体の `perception_range`(PC を含む)。**有効な範囲 r = `perception_range × 覚醒度の割合`**(切り捨て)。眠いほど狭く、眠っている間は 0。
- **知覚するのは、自分のセル + 距離 r まで(チェビシェフ距離 = (2r+1)×(2r+1) の正方形)**。r = 1 なら周囲 8 セル、**r = 0 なら自分のセルだけ**。**距離の方式は、すべての知覚(獲物・水の探索を含む)でチェビシェフ距離に統一**(現行の水の探索の、マンハッタン距離の 2 倍を置き換える)。担当 Region 内に限る(現状のまま)。
- **UI には、知覚の範囲しか見せない**: PC の画面に表示するのは、有効な知覚の範囲(自分のセル + 距離 r まで)の中の地形・個体だけ。**r = 0 のときは、自分のセルだけ**。サーバ側で、PC ごとに範囲内だけを返す(例: `GET /players/{id}/view` と、範囲内のイベントだけを返すストリーム)。**API の設計変更が要る**(現在の `snapshot` は世界全体を返す)。
- 知覚した地図(§3.1)は、将来、記憶の UI(認知地図)として表示できる。
- Player の標準値 20: 41×41 セル。CLI の画面(約 40×19 セル)より大きい。覚醒度の割合 0.5 で 10、0.25 で 5。

## 11. PC の助言(advice)と API(了承済みの方針)
