# 16 知覚・知覚した地図・NPC の判断の地図化・経路探索

**状態: 実装済み(2026-11-10)。結果は末尾「実装結果」** 仕様: `docs/spec/animal-memory-spec.md` §2・§3.1・§4.1・§4.4.1・§8・§10(作者確定 2026-11-10)。TODO G-43・G-45。
**依存**: なし(plan 14 は実装済み)。plan 17(記憶)・19(API)の前提。**動物の渇きによる死(経路探索がなく、障害物の手前で詰まる)を解消する**のが、最初の成果。

## 目的
1. 知覚の範囲を、個体ごとの能力にする(PC を含む。覚醒度をかけた有効な範囲。チェビシェフ距離に統一)。
2. 「見る」を action でなく、**知覚した地図(`PerceptMap`)の更新**にする。
3. NPC(動物・将来の人間)の判断を、**世界への直接の問い合わせから、地図への問い合わせ**に切り替える。
4. 地図の既知の陸を使った**経路探索(BFS)**を入れる(`step_toward` の詰まりを解消)。

## 実装順(段階)
### 16a 知覚の範囲と距離の統一(小)
- `SpeciesDef.vision` を `perception_range` に改め(標準値: Rabbit 6・Fox 8・**Player 20**)、`Animal.perception_range` に**発生時にコピー**(個体差なし。将来は遺伝子)。`perception_interval_ticks`(種の標準 **20**。個体にコピー)を追加。
- **有効な範囲 r = floor(perception_range × 覚醒度の割合)**(睡眠中は 0)。`Animal.effective_range()`。
- 知覚の距離を**チェビシェフ距離(正方形)に統一**。`Region.nearest_water`(現行: マンハッタン距離の 2 倍)・`nearest_prey` を、有効な範囲を使う形に(**この段階では、まだ世界への問い合わせのまま**)。
- `to_state` / `load_state` に追加(越境で引き継ぐ)。`/config` の `species` に標準値。
- **バランスへの影響の測定**: 視界が約 6 割に縮む(覚醒度の割合の平均)。`simulate`(2×2×16、複数 seed)で、渇き・飢えによる死の変化を測る(`docs/spec/animal-memory-spec.md` §6.4 旧・§10)。
### 16b Region の空間索引(中)
- 区画(D = 4)ごとの個体の索引(種ごと)と、水セルの索引を Region に持つ(`_index`/`_unindex`/`move` で更新)。知覚の走査(範囲内の資源の取得)を、全植物の走査から、範囲内の区画の引きにする(高速化の提案 C2 と共通)。
- 完了条件: 知覚の走査が、Region 内の植物数に依存しない(ベンチ)。結果は、索引なしと一致(等価性テスト)。
### 16c 知覚した地図 `PerceptMap`(大)
- 個体の状態として持つ(睡眠で消えない)。
  - **地形の層**: セル解像度(世界の大きさの 1 バイト配列。0 = 未知、1 = 陸、2 = 水、3 = 岩)。既知のセルは更新を飛ばす。薄めない。
  - **資源の層**: 区画(D = 4)ごとに、食料(植物)の種別の件数と tick。入眠のたびに、**忘却係数**をかけ、閾値未満を削除(忘却のパラメータは plan 17 で導入。ここでは、`PerceptMap.decay(factor, threshold)` の関数を用意)。
  - 動く個体(獲物)は、地図に残さない(現在の知覚だけ)、または短い期間だけ残す(要確認。plan の既定は「現在の知覚だけ」)。
- `perceive()`: **`perception_interval_ticks` ごと**(個体ごとの周期。個体のタイマー = `Entity.timers` の周期アクション。睡眠中はしない)に、自分のセル + 距離 r の範囲を走査して更新。更新の差分(`MapUpdate`)は、plan 17 のログ用に、フックを用意(この段階では保持しない)。
- **シリアライズ**: Region 越境(`handoff`)で運ぶため、地形の既知セルを、圧縮したバイト列(zlib)で `to_state` に入れる(目安: 数 KB)。公開用 `to_dict()` には含めない。
- **メモリ**: 1 個体 約 20 KB(128×128 の世界)。個体数が多い世界(1,000 匹)で約 20 MB。
### 16d NPC の判断の地図化と経路探索(大)
- `ai.think` を、**「知覚(地図の更新)→ 判断(`decide`)→ 実行」に分ける**。`decide` は、行動の提案(行動・対象・理由)を返す。NPC は実行し、PC は plan 19 で助言として保持する。
- 判断の入力を、**地図への問い合わせ**にする: 水(地形の層で、水に隣接する既知の陸)、食料(資源の層)。渇き・空腹のとき、地図の最寄りの目標へ向かう。目標がなければ探索(ランダムな移動)。**(想起の項は plan 17 で追加。判断の順序は「地図 → 想起 → 探索」)**。
- **経路探索**: 地図の既知の陸を BFS(範囲は上限付き、例: 64 歩)。経路を個体に保持し(目標・歩数のリスト)、塞がれたら再計算。`step_toward`(軸方向の貪欲な移動)は、経路が見つからないときの代替に残す。
- **Region 越境**: 知覚は担当 Region 内(現状のまま)。経路探索は、地図の既知の陸(世界の地形なので、Region をまたいで既知)を使える。越境先の知覚は、Region が変わってから。
### 16e 検証
- **再現テスト**: seed 1・2×2×16 の世界で、障害物の手前で詰まって渇きで死んだ個体(位置 (18, 3)、水 (18, 11)、陸の経路 11〜12 歩)の状況を、固定の配置で再現し、**水に着くこと**を確認。
- **A/B のシミュレーション**: 変更前(`step_toward`)と変更後で、2×2×16・3 seed・20 日(`simulate --scale-animals`)の、渇き・飢えによる死の数と、動物の存続日数を比較。
- ベンチ: 1 tick あたりの時間の増加(目標: 既定の世界で +20% 以内)。

## 完了条件(テスト)
- 有効な範囲 = floor(範囲 × 覚醒度の割合)。r = 0 で自分のセルだけ。チェビシェフ距離(正方形)。睡眠中は知覚しない。個体の値は、発生時に種の標準値をコピー(Player 20)。
- 地形の更新(既知を飛ばす)、資源の層の更新と忘却、`perception_interval_ticks`(20)ごとの更新。越境でも地図が引き継がれる(`to_state` の往復)。
- `decide` の分離。NPC は地図だけで判断する(世界への問い合わせを使わない)ことを、テストで確認(世界への問い合わせ関数を無効にしても動く)。
- BFS: 障害物の迂回、到達不能、上限、経路の再計算、決定論。
- 再現テストと A/B のシミュレーション(渇きによる死の減少)。個体数の推移・決定論(同じ seed → 同じ結果)。
- 性能: 知覚・BFS・地図の更新が tick の予算内。

## リスク
- 視界の縮小(覚醒度)と地図への切り替えで、生態系のバランスが変わる(G-2)。
- 地図のメモリと越境のコスト(圧縮、既知セルだけ)。
- 判断の遅れ(地図は最大 20 tick 古い。Rabbit の判断は 20 tick ごとなので、実質同じ)。
- CLI・API への影響は plan 19(Player の知覚の範囲の表示)。

## 実装結果(2026-11-10)
- **16a**: `SpeciesDef.perception_range`(Rabbit 6・Fox 8・**Player 20**。`vision` を改名)・`perception_interval_ticks`(20)。`Animal.perception_range`・`perception_interval_ticks` を発生時にコピー。`effective_range(region)` = floor(範囲 × 覚醒度の割合)(眠っている間は 0)。知覚は「自分のセル + 距離 r(チェビシェフ距離)」。`validate_config` の視界の警告は、NPC の知覚だけが対象。
- **16b**: Region に区画(4×4)ごとの個体の索引(`_buckets`)と、植物だけの索引(`_plant_buckets`・`plant_version`)。`entities_in_range`・`plants_in_range`。
- **16c**: `core/percept_map.py`(`PerceptMap`: 地形 = セル解像度の 1 バイト配列、資源 = 区画ごとの件数・見た tick・代表のセル。`decay`・`window`・圧縮した `to_state`)、`core/perception.py`(`perceive`: 既知の行を飛ばす・同じ位置・範囲・植物の版番号なら走査を省く。`scan_mobile`: 動く個体は地図に残さない)。個体の知覚は `perception_interval_ticks` ごと(位相を散らす)。
- **16d**: `core/ai.py` を `decide`(副作用なし。`Decision`)/`execute`/`think` に分離。**判断は地図だけ**(世界への問い合わせを使わない)。経路探索 `core/pathfinding.py`(BFS。**未知のセルを通れると仮定**して計画し、塞がれたら再計画。失敗した目標の再探索は 300 tick 間引く)。
- **16e**: 渇きで死んだ状況(seed 1・2×2×16・位置 (18, 3))を再現するテスト: 約 1,000 tick で水に着いて飲む。**小さな世界の 20 日 × 3 seed で、渇きによる死は 0**(従来は Fox が 3〜4 日目までに全滅、Rabbit は 7 日目・12 日目に絶滅)。
- テスト: `server/tests/test_perception.py`(23 件)。
- **性能**: 既定の世界(4×4×32、Rabbit 32・Fox 4)で、1 tick あたり 約 0.63 ms → **約 0.84 ms(+33%)**(知覚・経路探索・判断の地図化の分)。目標(+20%)をやや超える。知覚の最適化(既知の行のスキップ・植物の索引・同じ位置の省略)で改善済み。
- **残る課題**: 飢えた個体は入眠圧が 0 になって眠れず、覚醒度 0 で意識消失を繰り返す(確定済みの仕様の帰結)。草があっても、遠い目標へ向かう途中で意識消失し、飢えて死ぬ(バランス調整 G-2)。
